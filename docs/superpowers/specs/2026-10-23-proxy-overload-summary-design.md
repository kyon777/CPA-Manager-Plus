# 代理过载聚合统计设计

- 日期：2026-10-23
- 状态：设计已确认，等待规格审阅
- 范围：仅 CPA Manager Plus（CPAM）
- 不触碰：CPA Core、`cli-proxy-api`、凭证 Token、计费/额度采集、调度与巡检决策

## 1. 目标

在凭证列表中保留现有“代理 IP 筛选 / 已保存代理池”能力，并新增独立的“代理过载统计”入口，用于从最近三天有请求的当前凭证中，按**当前** `proxy_url` 聚合识别精确的 Codex 服务过载信号。

管理员可以：

1. 查看每个当前代理下最近三天有请求的账号数量；
2. 查看这些账号各自最近最多九条请求中，发生过 `HTTP 502 + server_is_overloaded` 的账号数量；
3. 查看没有该过载信号的账号数量和过载比例；
4. 勾选任意代理并复制为一行一个的可用代理 URL，以便人工挑选零过载或低过载代理。

本功能是只读诊断。它不触发额度刷新、认证更新、巡检、代理验证、优先级调整、凭证写入或任何面向 Provider 的 CPA 业务请求；唯一的 CPAM → CPA 管理端认证清单读取见第 6 节，且不对账号发起检测或额度调用。

## 2. 已确认产品决策

| 项目 | 决策 |
| --- | --- |
| 原有功能 | 现有“代理 IP 筛选 / 已保存代理池”保留，新增独立入口，不替换、不删除已保存代理数据。 |
| 账号范围 | 当前 CPA 认证清单中仍存在、且过去 72 小时至少有一条请求记录的账号；不因其当前启用/禁用状态排除。 |
| 请求样本 | 每个账号仅取过去 72 小时内按 `timestamp_ms desc, id desc` 排列的最多 9 条。 |
| 过载判定 | 仅 `failed=true`、`fail_status_code=502` 且错误码精确为 `server_is_overloaded`。 |
| 非过载 | 账号最近最多 9 条中不存在上述精确过载信号。它不是“绝对健康”承诺；401、429、407、EOF 等仍属于非过载。 |
| 代理归属 | 按账号**当前** `proxy_url` 归属。账号三天内曾换代理时，旧请求归入当前代理；不新增历史代理存储。 |
| URL 归并 | 复用现有语义：去首尾空白、忽略任意数量末尾 `/`；分组使用规范化值，复制保留一个可直接使用的原始当前 URL。 |
| 自动刷新 | 弹窗不加入列表自动刷新；仅首次打开和管理员点击“刷新统计”时运行。 |
| 数据写入 | 不新增 `usage.sqlite` 写入、迁移或代理历史表。 |

## 3. 非目标

- 不修改、构建、重启、部署 CPA Core 或 `cli-proxy-api`；
- 不读取每个账号的原始认证 JSON，不调用逐账号下载接口；
- 不调用 `credential-runtime-metadata` 的 80 路/逐目标路径；
- 不使用浏览器加载全部请求明细后聚合；
- 不把普通 502、HTTP 500、503、429、代理 407、EOF 或消息相似错误混入“服务过载”；
- 不为历史事件补录代理 URL，也不试图回溯换代理前的真实代理归属；
- 不改变现有代理异常检测、代理出口 IP 自检、代理替换、优先级降级、自动 Token 更新或凭证列表筛选逻辑。

## 4. 用户界面

### 4.1 入口

凭证列表批量工具栏保留现有：

```text
代理 IP 筛选
```

并新增：

```text
代理过载统计
```

新入口与当前凭证勾选状态无关；统计范围固定为全部当前凭证和最近三天请求，不因分页、搜索或当前列表筛选缩小。

### 4.2 统计弹窗

弹窗标题为“代理过载统计”，顶部固定展示：

- 统计生成时间；
- 统计窗口起点与“最近 3 天”说明；
- “每账号最多最近 9 条请求”；
- “按当前代理归属”；
- 活跃账号总数、未配置代理账号数、可比较代理数、发生过载的账号总数。

主体表格字段：

| 字段 | 含义 |
| --- | --- |
| 勾选 | 用于复制代理 URL；支持当前筛选结果的全选。 |
| 当前代理 URL | 当前 CPA 认证清单返回的原始 URL。 |
| 活跃账号 | 该代理下三天内至少有一条请求的账号数。 |
| 有过载 | 最近最多 9 条中至少一次命中精确服务过载的账号数。 |
| 无过载 | 活跃账号减去有过载账号。 |
| 过载率 | `有过载 / 活跃账号`，以百分比显示。 |

默认排序：

1. `有过载 = 0` 的代理优先；
2. 同类按活跃账号数倒序；
3. 再按规范化代理 URL 稳定排序。

弹窗支持最小必要操作：

- 全部；
- 仅零过载；
- 仅发生过载；
- 刷新统计；
- 勾选并“复制已勾选 URL”。

复制值为 LF 分隔纯文本，末尾不额外追加空行。复制只包含当前可见、被勾选的代理 URL，不包含账号数、错误内容或任何 Token。

## 5. 接口契约

新增受现有 Panel Bearer 认证保护的只读接口：

```text
GET /v0/management/monitoring/proxy-overload-summary
```

该版本不接受时间窗口、每账号条数、provider 或账号列表等可放大负载的客户端参数。服务端固定使用 72 小时和 9 条限制。

成功响应：

```json
{
  "generated_at_ms": 1792752183000,
  "window_start_ms": 1792492983000,
  "active_account_count": 2815,
  "missing_proxy_account_count": 4,
  "proxy_count": 145,
  "overloaded_account_count": 326,
  "proxies": [
    {
      "proxy_url": "http://107.167.22.100:8888",
      "active_account_count": 70,
      "overloaded_account_count": 30,
      "non_overloaded_account_count": 40,
      "overloaded_rate": 0.428571
    }
  ]
}
```

安全边界：

- 响应绝不包含邮箱、账号名、认证文件名、`raw_json`、`fail_body`、请求正文、Token、Trace ID；
- 代理 URL 是本功能的明确展示/复制对象，可沿用既有面板授权边界，但不得写入服务端日志、错误字符串或 SQLite；
- 响应附加 `Cache-Control: no-store`，避免浏览器/反代持久缓存含代理凭据的 URL。

## 6. 后端架构与数据流

### 6.1 当前代理快照：恰好一次 CPA 调用

CPAM 新建专用的当前代理快照读取器，调用配置好的 CPA 管理端：

```text
GET /v0/management/auth-files?include_proxy_url=1
```

规则：

1. 每次统计计算最多调用一次；该调用由 CPAM 服务端执行，浏览器不直接访问 CPA；
2. 正常 CPA 运行路径从认证管理器当前内存状态导出 `proxy_url`，不读取 5000 个磁盘 JSON；
3. 快照读取器仅解析统计所需字段：认证文件快照、`auth_index`、provider、Codex 身份证据和 `proxy_url`；
4. 若 CPA 不能提供此轻量清单，立即失败并提示管理员重试；严禁回退为原始文件扫描、逐账号 `/download` 或 `credential-runtime-metadata`；
5. 快照在本次请求内存中存在，响应后释放，不持久化。

### 6.2 身份映射

快照中的每个凭证建立两组内存映射：

```text
凭证稳定身份（auth_file_snapshot + auth_index + provider/Codex 证据）
    -> 规范化 proxy key

规范化 proxy key
    -> 稳定选出的一个原始当前 proxy_url
```

身份匹配必须复用/抽取现有 `usageevent` 的 Codex workspace/member 防串号规则。不得仅以邮箱或展示名匹配，不得让共享 Workspace 的成员历史错误合并。

空 `proxy_url` 的账号依然参与“最近三天有请求”的识别，但只增加 `missing_proxy_account_count`，不创建空代理行。

### 6.3 受限批量 SQLite 聚合

不得复用现有可能对每个目标单独查询的 `RecentAccountRequests` 路径。新增专用只读仓储方法：

```text
RecentProxyOverloadEvidence(ctx, credentialTargets, sinceMS, perCredentialLimit=9)
```

实现约束：

1. 凭证目标按最多 500 个一批；5,000 个账号最多约 10 次 SQLite 集合查询，而不是 5,000 次；
2. 每批使用 `VALUES` CTE、现有 `(auth_file_snapshot, auth_index, timestamp_ms desc, id desc)` 与 legacy source 索引，以及 `ROW_NUMBER() OVER (PARTITION BY request_index ...)`；
3. SQL 只读取 `id`、时间、失败位、HTTP 状态、`header_error_code`、安全 `fail_summary` 等诊断字段；
4. SQL 限定 `timestamp_ms >= sinceMS`，每个目标最多返 9 条，全部 5,000 个账号的理论上限为 45,000 条轻量行；这些行仅在 CPAM 内存中短暂用于精确判定，绝不回传浏览器；
5. Go 使用一个共享的精确检测函数判定：`failed && status == 502 && (header_error_code == "server_is_overloaded" || fail_summary 存在完整代码 token)`；`fail_summary` token 检查必须采用非字母数字下划线边界，避免 `not_server_is_overloaded` 类误命中；
6. 批次在一个短生命周期的只读数据库事务内按顺序读取，保证结果快照一致，同时避免并发读任务争抢 SQLite；
7. 所有批次结果由服务层按当前规范化代理 key 聚合，计数时每个账号对同一代理最多贡献一次“有过载”或“无过载”。

数据库索引维护尚未完成或必需的最近请求索引缺失时，接口明确返回“数据库索引维护未完成，代理过载统计暂不可用”，不降级为 N+1 查询。

### 6.4 并发与缓存

```text
浏览器打开/刷新弹窗
        ↓
单一 CPAM 统计请求
        ↓
同一时刻相同统计请求 singleflight 合并
        ↓
一次 CPA 清单 + 最多十个集合 SQL 批次
```

- 同一份统计正在执行时，多个页面/重复点击共用一个执行任务；任一浏览器取消不会错误取消仍有等待者的共享任务；
- 成功结果仅保留进程内 15 秒短缓存，防止重复打开弹窗造成短时间重算；
- “刷新统计”绕过已完成缓存，但仍会加入正在执行的同参数任务；
- 不做后台定时刷新、不把统计接入凭证列表 10 秒/60 秒刷新链路；
- 上游 CPA 快照、数据库读取与总请求设受控服务端期限；超时必须是明确失败，不能留下半份统计结果。

## 7. 错误与状态处理

| 场景 | 前端行为 | 后端行为 |
| --- | --- | --- |
| 初次加载 | 表格骨架屏、按钮防重入 | singleflight 统计。 |
| CPA 清单失败/超时 | 显示“无法取得当前代理映射”，提供重试 | 不扫描文件，不返回旧代理映射。 |
| SQLite 索引维护中/缺失 | 显示维护提示，不显示不完整统计 | 快速失败，不走 N+1 回退。 |
| SQLite 查询失败/超时 | 保留弹窗内上一份完整成功结果，标记“刷新失败，显示上次成功数据”；若无旧结果则显示错误 | 丢弃本次部分结果。 |
| 无三天内请求 | 显示空态“最近三天没有可统计请求” | 返回零计数与空数组。 |
| 所有活跃账号无代理 | 显示无代理账号数和空表 | 不制造空 URL 分组。 |
| 复制失败 | 显示“复制失败，请手动复制”，不清空勾选 | 不发起额外后端请求。 |

## 8. 前端状态边界

- 弹窗状态完全局部化，不改凭证列表 inventory、分页、搜索、排序、当前选择或自动刷新开关；
- 打开统计不触发 `account-history`、`account-window-usage`、`credential-runtime-metadata`、额度刷新或 Header 快照请求；
- 关闭弹窗后取消尚未需要的浏览器等待请求；服务端仅在没有其他等待者时才停止统计；
- 统计表最多渲染代理行数，而非账号行数；不向前端下发 5,000 个账号或最多 45,000 条请求事件；
- 原有“代理 IP 筛选”弹窗、保存代理池、未使用代理筛选、代理替换及批量 `proxy_url` 更新不改动。

## 9. 测试与验收

### 9.1 仓储与服务单元测试

1. 5,000 个凭证目标被分割为最多 10 个 500 目标集合查询；不产生逐账号查询；
2. 每个凭证只采纳三天内时间倒序前 9 条；第 10 条及更早请求不影响结果；
3. 恰有一个精确 `502 + server_is_overloaded` 时，账号计入有过载一次；
4. 普通 502、502 EOF、502 `request failed`、500、503、429、407、401、`failed=false` 与 `not_server_is_overloaded` 均不命中；
5. `header_error_code` 精确值优先；安全摘要中完整代码 token 的兼容路径正确；
6. Codex 同 workspace 多成员、空 auth index、legacy source 记录与冲突身份均遵循现有安全身份语义；
7. 尾部 `/`、周围空白的等价 URL 合并；原始可用 URL 稳定输出；
8. 当前无代理账号被正确计数但不在表内；
9. 统计前后 `usage_events` 行数、事件哈希和数据库 schema 完全不变。

### 9.2 HTTP 与并发测试

1. 假 CPA 服务断言每次统计最多收到一次 `auth-files?include_proxy_url=1`；
2. 断言不会请求 `/download`、`credential-runtime-metadata` 或任何逐凭证端点；
3. 同时发起多次接口调用时只执行一次 CPA 快照和一组 SQLite 批次；
4. 缓存命中、显式刷新、上游失败、索引未就绪、数据库超时和无数据空态均有稳定 HTTP/JSON 契约；
5. 响应和日志不含 Token、`raw_json`、`fail_body`、邮箱、认证文件名或 Trace ID；
6. 认证中间件与既有管理端权限保持有效。

### 9.3 前端测试

1. 新入口存在，旧“代理 IP 筛选”入口仍存在且行为不变；
2. 默认零过载优先排序、筛选、全选、单选、取消选择稳定；
3. 复制内容仅为被勾选 URL，LF 分隔、无尾部空行；
4. 初次加载、刷新、错误、保留上一份结果、空态、无代理计数状态均正确；
5. 打开/关闭弹窗不触发历史用量、额度窗口、运行时元数据或凭证列表刷新请求；
6. 统计结果不受当前列表分页/搜索/已启用筛选影响。

## 10. 部署与回归边界

- 只构建、部署 CPAM；绝不重启、构建、修改 CPA Core 或 `cli-proxy-api`；
- 计费、Credits、额度、历史用量、最近请求、自动刷新、Token 自动更新、优先级降级、巡检、代理出口 IP 自检与代理替换均必须回归验证；
- 后续“更新 CPAM”时此功能属于必须保留的二改：独立代理过载统计入口、一次 `include_proxy_url=1` 快照、受限批量只读请求聚合、无 N+1/无文件扫描边界；
- 不向上游推送；未来实现合并后仅可推送私有 `origin/lo/custom`。

## 11. 成功标准

在约 5,000 凭证和高并发请求环境中，管理员能够主动打开统计弹窗并得到按当前代理聚合的三天/九请求过载数据；CPAM 每次计算至多一次 CPA 轻量清单读取与有限数量集合式 SQLite 查询，浏览器不接收账号级请求明细，现有凭证列表不会因为该功能增加后台卡顿、N+1 网络流量或计费风险。
