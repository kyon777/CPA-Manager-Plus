# 批量复制授权文件 JSON：设计

- 日期：2026-10-23
- 状态：已确认设计与规格；实施计划见 `docs/superpowers/plans/2026-10-23-batch-copy-auth-json-export.md`
- 范围：仅 CPA Manager Plus（CPAM）
- 不触碰：CPA Core、`cli-proxy-api`、账号调度、计费、额度采集、窗口用量、历史请求、优先级、巡检与自动更新。

## 1. 目标

管理员在凭证列表勾选一批账号（典型为当前页 50 个）后，可从“更多”菜单选择“复制授权文件数据”。CPAM 将**实际勾选的逻辑账号**导出为一个可直接粘贴到另一台 CPA 的顶层 JSON 数组：

```json
[
  { "type": "codex", "email": "a@example.com" },
  { "type": "codex", "email": "b@example.com" }
]
```

输出保留每个原始授权对象的字段，包括 `proxy_url`、`note`、`priority` 和认证字段；不刷新、转换、写回或修改任何源文件。

已确认的行为：

1. 一个物理 JSON 文件中包含多个账号时，只导出实际勾选的对象，绝不附带未选账号。
2. 某些账号读取失败时，成功对象仍复制；失败账号以文件名和安全错误码单独显示。
3. 正常路径直接写入系统剪贴板；只有剪贴板写入失败时才显示 JSON 结果框，供再次复制或下载。

## 2. 方案选择

### 采用：CPAM 服务端受控导出

新增 Manager Server 端点：

```http
POST /v0/management/auth-files/export-selected
Content-Type: application/json
Authorization: Bearer <panel-token>
Cache-Control: no-store
```

前端只提交定位所需的无密钥身份字段：

```json
{
  "targets": [
    {
      "clientKey": "…",
      "fileName": "a@example.com.json",
      "authIndex": "…",
      "runtimeId": "…",
      "provider": "codex",
      "accountId": "…",
      "accountSnapshot": "a@example.com"
    }
  ]
}
```

Manager Server 按物理文件名去重，受控读取 CPA 原始文件，精确抽取每个目标对象，最后返回：

```json
{
  "records": [
    { "type": "codex", "email": "a@example.com" }
  ],
  "exported": 1,
  "failed": [
    { "clientKey": "…", "fileName": "missing.json", "code": "credential_not_found" }
  ]
}
```

浏览器只复制 `records` 本身序列化后的顶层 JSON 数组；响应信封绝不复制进剪贴板。

### 不采用：浏览器逐个下载并拼接

现有批量下载对每个文件串行请求 `/auth-files/download`。它会将 50 个选择变成 50 次浏览器请求和大量前端解析，容易拖慢列表；也不易从共享数组源文件中准确抽取已选对象。

### 不采用：临时 JSON 文件导出

服务端落地临时导出文件会增加敏感数据留存、清理与权限边界，且不符合直接复制工作流。下载仅作为浏览器剪贴板失败后的客户端 Blob 兜底，不创建服务端临时文件。

## 3. 前端交互

1. 在已选账号浮动工具栏的“更多”菜单中，紧邻“批量下载”增加“复制授权文件数据”。
2. 点击后菜单项和同一批量操作区域锁定，显示“正在整理 N 个授权文件…”，阻止重复提交。
3. 操作期间不调用额度刷新、最近请求、历史用量、`account-window-usage`、自动更新、巡检或优先级接口，也不重算列表。
4. 全部成功：显示“已复制 N 个授权文件数据”。
5. 部分成功：复制成功记录，显示“已复制 S/N 个；F 个失败”，可查看失败文件名和安全错误码。
6. `navigator.clipboard.writeText` 失败时，打开仅内存持有的结果框；提供“再次复制”和“下载 JSON”。关闭即清空内容。
7. 保留选中状态；导出不是变更操作，不重新加载凭证列表。

## 4. 服务端精确提取流程

```text
已选 AccountRow[]
  -> 浏览器提交目标身份（没有 token）
  -> Manager Server 验证管理员鉴权、数量与身份格式
  -> 按物理 fileName 去重
  -> 最多 8 路并发从 CPA 下载每个物理源文件
  -> 解析原始 JSON
  -> 依据 authIndex/runtimeId/provider/accountId/accountSnapshot 精确匹配已选逻辑账号
  -> 按用户原选择顺序构造 records[]
  -> 返回 records[] 和 failed[]
  -> 浏览器一次性 stringify + 一次性写剪贴板
```

规则：

- 一个物理源文件只能下载一次；其中多个被选账号在同一次解析内完成抽取。
- 单对象源文件与数组源文件均支持。
- 身份不唯一、文件不存在、源内容非法、运行时虚拟账号没有可导出物理源时，目标进入 `failed[]`。
- 任何身份错配都拒绝导出，不能按文件名模糊退化为整文件导出。
- 输出对象保持源对象原样；不调用 token 刷新、不进行导入转换，不补写字段。

## 5. 性能与资源边界

- 每次最多 300 个逻辑账号，与既有 CPA JSON 粘贴导入上限一致。
- 最终可复制 JSON 最大 48 MiB，与既有粘贴入口上限一致。
- 物理源文件读取并发固定上限为 8；不建立持久队列、不占用自动恢复或巡检队列。
- 超过 300 条或聚合 JSON 超过 48 MiB 时，整体返回明确错误，不复制半截数组。
- 单个文件读取失败不使整个批次失败；仅将该文件关联的目标记录为失败。
- 前端仅接收一次聚合响应，不做 50 次下载、50 次渲染或全量账号重算。

## 6. 敏感数据边界

- 认证 JSON 仅在 CPA、Manager Server 请求内存、HTTPS 响应和管理员本机剪贴板中流动。
- 不写 SQLite、不写临时文件、不进入缓存、不进入任务队列、不进入诊断或审计正文。
- 响应发送 `Cache-Control: no-store`；失败响应不回显原始 JSON、token、代理认证信息或 CPA 原始错误正文。
- 服务端日志仅允许记录选择数量、唯一物理文件数量、成功/失败计数、耗时和固定错误码。
- 复用现有面板管理员鉴权；未授权、超量、无效身份、跨身份错配均在导出前拒绝。

## 7. 错误码与前端呈现

| 代码 | 含义 | 是否复制其他成功记录 |
| --- | --- | --- |
| `credential_not_found` | 源文件不存在、账号已被删除或当前无法定位 | 是 |
| `identity_mismatch` | 源文件存在，但身份不再匹配选择的逻辑账号 | 是 |
| `invalid_source_json` | 源文件不是可解析的对象或数组 | 是 |
| `source_unavailable` | CPA 源文件读取失败或超时 | 是 |
| `runtime_only` | 运行时账号没有可复制的物理源文件 | 是 |
| `export_limit_exceeded` | 超过 300 条或 48 MiB 总边界 | 否，整体不复制 |

失败详情只展示账号标签、文件名和上表代码的中文文案；不显示 token、原始 JSON、代理 URL 或上游错误正文。

## 8. 验证范围

后端：

1. 50 个独立文件导出为严格 50 个对象。
2. 共享数组源文件只导出已选对象；同一文件只发生一次下载。
3. 多目标输入保留前端选择顺序。
4. 个别 `credential_not_found`、身份错配、坏 JSON 与读取失败不会污染成功数组。
5. 超过记录数或字节数上限时没有不完整成功响应。
6. 未授权、恶意 `authIndex`、文件名替换、身份错配请求被拒绝。
7. 错误、日志与响应体不泄漏 token、代理认证或原始源内容。

前端：

1. “更多”菜单存在复制入口，运行中可防重。
2. 全成功、部分成功和剪贴板失败兜底文案准确。
3. 剪贴板内容是合法顶层数组，不含 `failed` 信封字段。
4. 导出期间不发起额度、窗口用量、最近请求、历史用量或列表刷新请求。
5. 复制出的数组能够被现有“粘贴认证 JSON → CPA 认证 JSON”流程接收，并按账号生成独立文件。

## 9. 非目标

- 不新增 CPA Core API，不修改 CPA Core 行为。
- 不自动导入到远端服务器；本功能只复制可携带 JSON。
- 不替代现有“批量下载”功能，也不删除现有批量操作。
- 不修改 API 计费、请求调度、优先级、自动恢复或巡检状态。
