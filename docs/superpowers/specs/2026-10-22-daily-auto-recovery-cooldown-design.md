# Codex 自动凭证更新：24 小时冷却设计

**日期：** 2026-10-22  
**状态：** 已确认  
**目标：** 将已启用 Codex 凭证的自动重登录恢复从“同一凭证永久仅一次”改为“同一凭证滚动 24 小时最多一次”。

## 范围

- 仅修改 CPA Manager Plus（CPAM）的 Token Recovery 自动信号与持久化任务状态。
- 仍然只接受：运行时开关开启、当前 CPA 文件已启用、Codex、可确认 HTTP 401 的信号。
- 不改 CPA Core / `cli-proxy-api`、计费、usage 采集、请求调度、额度、优先级降级或人工恢复 API。

## 规则

1. 同一物理凭证以现有稳定 identity（文件名 + `auth_index` / 邮箱兼容定位）去重。
2. 自动任务被 worker 实际领取时写入 `auto_attempted_at_ms`；该时间是最近一次外部 Token Acquisition 已开始的时间。
3. 从该时间起 24 小时内，重复 HTTP 401 不得新建或重排自动任务；已排队/运行任务始终去重。
4. 满 24 小时后，仅在出现一条新的、合格的 HTTP 401 信号时，才允许将终态自动任务重新排为 `auto_queued`。系统不得按时钟自行扫描或重试。
5. 自动成功与自动失败都进入同一 24 小时冷却，避免大规模失败账号反复请求 Token Acquisition。
6. 人工恢复照常可随时排队；人工操作不占用、不清除、不延长自动恢复冷却。
7. 旧数据不迁移、不清空：历史 `auto_attempted_at_ms` 被视为最近自动尝试时间；已超过 24 小时的旧记录会在下一次合格 401 信号到来时自然恢复自动资格。
8. 无 `auto_attempted_at_ms` 的旧终态 auto 任务以 `started_at_ms`、`completed_at_ms`、`created_at_ms` 的首个有效时间回填后再计算冷却。

## UI 与审计

- `auto_attempted_at_ms` 保留为持久化审计字段，不暴露 Token、原始认证 JSON 或代理密码。
- UI 需要避免使用“永久仅一次”的语义；在冷却期显示“24 小时内已自动更新”，冷却期结束后显示最近自动更新历史而不阻止下次合格 401。
- 现有自动任务状态、失败原因、人工更新按钮继续可用。

## 并发与故障边界

- 同一身份仍通过 SQLite 事务和现有 queued/running 状态去重；并发 401 不会产生两个自动任务。
- AutomaticSignalGate 在冷却期内直接抑制信号，避免不必要的 CPA `auth-files` 验证调用。
- Repository 在事务内再次检查冷却，作为 Gate 之后的最终并发安全边界。
- 服务重启中断的自动任务仍保留其尝试时间；下一次合格信号需等待剩余冷却后才可重新排队。

## 验收

1. 自动任务一经领取，24 小时内重复合格 401 不会重新排队或再次调用 Token Acquisition。
2. 24 小时外的新合格 401 会重排同一自动任务，并仅在新 worker 领取时更新尝试时间。
3. 自动成功和失败均遵守冷却。
4. 人工恢复不改变自动冷却时间。
5. 旧终态自动任务兼容回填时间后遵守冷却。
6. 仅已启用 Codex HTTP 401 信号可触发；计费和 CPA 调度回归不受影响。
