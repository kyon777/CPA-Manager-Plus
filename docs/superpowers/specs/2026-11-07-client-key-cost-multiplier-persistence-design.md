# 客户端 Key 成本倍率本地持久化设计

## 目标

让 Usage Analytics 的“客户端 Key 消耗排行”倍率设置在同一浏览器中跨刷新、跨离开/返回页面保留。默认值仍为 `1`；用户输入 `0.3` 后，当前表格立即按 `0.3` 重绘，后续重新打开页面也自动恢复 `0.3`。

## 边界

- 只保存浏览器本机的展示偏好，不写入服务器、SQLite、CPA Core、CPAM 运行配置或计费记录。
- 只影响客户端 Key 排行表中括号里的“倍率金额”；原始预估成本、排序、汇总、筛选、导出和所有计费逻辑不变。
- 不把倍率写入 URL，分享链接不会携带个人显示偏好。
- 不新增重置按钮；输入 `1` 即恢复默认展示，避免增加无必要 UI。

## 设计

复用现有 `usageAnalytics.uiState` localStorage 记录，而非新增第二个 key。该记录新增 `apiKeyCostMultiplier: number`：

1. 读取时，缺失、空、负数、非有限数或损坏值统一回退为 `1`，因此旧浏览器数据天然兼容。
2. `UsageAnalyticsPageInner` 初始化倍率输入框时从该 UI state 读取；localStorage 不可用或抛出异常时保持内存默认值 `1`。
3. 每次输入变化都保留原始输入文本供编辑体验使用，同时把归一化后的非负有限值写回 UI state。输入中间态（空、`-`、非法文本）暂按 `1` 保存；失焦时把输入框显示归一为 `1` 或合法数字。
4. 既有 `writeUsageAnalyticsUiState` 的筛选/标签写入必须保留该字段，避免任一普通筛选操作意外抹掉倍率。

## 错误与性能

localStorage 访问仍由现有 `try/catch` 包裹：浏览器拒绝存储时不提示错误，只退化为当前会话内的内存展示。写入仅发生在用户编辑紧凑数字输入框时，不触发网络请求、排序、全量数据重算或任何后端负载。

## 验收

1. 无历史设置时，倍率输入为 `1`。
2. localStorage 中的 `0.3` 进入页面后输入框为 `0.3`，倍率金额按 `0.3` 显示。
3. 修改为 `0.3` 后刷新/重新挂载页面仍是 `0.3`。
4. 非法持久化值回退到 `1`，不会影响列表渲染。
5. 修改倍率不调用 `usage.refresh`，不改变原始 `estimatedCost`。
