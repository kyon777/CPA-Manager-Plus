# 客户端 Key 预估成本倍率显示设计

## 目标

在“客户端 Key 消耗排行”表格中，为现有的“预估成本”增加一个纯前端倍率金额展示。用户设置倍率（默认 `1`）后，表格在原始金额后以括号显示 `原始预估成本 × 倍率` 的结果；不改变任何计费逻辑、后端数据或其他页面统计。

## 范围与非目标

### 纳入范围

- 仅作用于 Usage Analytics 的 `apiKeys` 页面中的客户端 Key 排行表格。
- 在该表格标题区域、现有搜索框旁增加“倍率设置”输入控件。
- 默认倍率为 `1`，支持非负有限小数，例如 `0.3`。
- 预估成本单元格保持单行展示，例如：`$1,026.47（倍率 $307.94）`。
- 倍率改变后立即重新渲染当前表格，无网络请求。
- 原始金额和倍率金额都沿用现有货币格式化函数与当前语言环境。

### 明确不做

- 不修改 CPAM/CPA Core、服务端 API、数据库、派生表或计费记录。
- 不修改摘要卡片、趋势图、成本占比图、异常表、详情面板或导出数据。
- 不用倍率金额替换原始预估成本，也不改变当前排序、成本占比和筛选语义。
- 不跨页面或跨浏览器持久化倍率；刷新页面后恢复默认 `1`。

## 交互设计

### 控件

- 标签：`倍率设置`（各语言通过 i18n 提供）。
- 控件类型：紧凑数字输入框。
- 初始值：`1`。
- `min=0`、`step=0.01`；不允许负数。
- 输入为空或不是有限数字时，展示层暂时按 `1` 计算；失焦时归一化为合法值，避免用户编辑小数过程中出现 NaN 或异常金额。
- 倍率为 `0` 时显示 `（倍率 $0.00）`，不隐藏该值。

### 金额展示

客户端 Key 行的“预估成本”保持原值，并在同一行追加括号：

```text
$1,026.47（倍率 $307.94）
```

当倍率为 `1` 时仍显示括号中的结果，便于用户确认当前倍率；金额格式与原有 `formatMetricValue('estimatedCost', value)` 完全一致。

## 数据流与边界

1. `UsageAnalyticsPageInner` 持有页面级 `costMultiplierInput` 状态，初始为字符串 `"1"`。
2. 由一个纯函数把输入归一化为非负有限数；非法或空输入返回 `1`。
3. `apiKeys` 分支把归一化倍率传给 `RankTable`。
4. `RankTable` 仅在 `type === 'apiKey'` 且有倍率参数时，为 `row.estimatedCost` 计算展示金额。
5. `row.estimatedCost` 本身不被复制修改；其他 `RankTable` 类型不接收倍率参数，因此模型和凭证表行为保持不变。

## 组件边界

- `UsageAnalyticsPage.tsx`：负责控件状态、输入处理、i18n 文案传递和 apiKeys 表格 wiring。
- `RankTable`：负责客户端 Key 表格的单元格展示；不负责保存或解释计费数据。
- 可在 `usageAnalyticsModel.ts` 放置/导出小型归一化纯函数，便于单元测试；不新增服务端模型字段。
- `UsageAnalyticsPage.module.scss`：只增加控件和括号文本的紧凑布局样式，避免改变其他表格。
- 四套 locale 文件新增控件标签和倍率前缀文案。

## 精度与显示规则

- 计算使用 JavaScript 数字乘法，输入和原始成本均要求为有限数。
- 不做金额四舍五入后再参与计算；先计算完整数值，再交给现有金额格式化函数显示。
- `estimatedCost` 缺失或非有限时沿用现有显示行为，倍率金额不额外制造数值。

## 测试策略

- 纯函数测试：默认输入、`0.3`、`0`、空字符串、非法字符串、负数和无限值的归一化结果。
- 页面/组件测试：
  - apiKeys 表格显示原始金额和括号倍率金额；
  - 修改倍率后金额即时变化；
  - 默认倍率为 `1`；
  - model/credential 表格不出现倍率文本；
  - 不触发新的 API 请求或修改原始 `estimatedCost`。
- 运行现有 Usage Analytics 测试集与 TypeScript/ESLint 检查。

## 验收标准

1. 打开客户端 Key 消耗排行时，倍率输入默认显示 `1`。
2. 设置 `0.3` 后，示例 `$1,026.47` 显示为 `$1,026.47（倍率 $307.94）`。
3. 切换时间范围、筛选或重新加载数据后，倍率仍只影响当前表格的展示，不改变服务端请求参数。
4. 页面其他金额、仪表盘和实际计费结果与改动前一致。
