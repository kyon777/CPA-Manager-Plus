# 凭证列表实时刷新开关设计

**状态：** 已确认，待实施`r`n**范围：** 仅 CPAM 前端 `apps/web`；不变更 CPA Core、`cli-proxy-api`、计费、额度写入或调度逻辑。

## 目标

在高并发、多账号的凭证列表中，操作者可以先手动取得一次最新快照、选择“最近请求”排序或错误筛选器，然后冻结列表画面进行人工观察。关闭实时刷新必须只暂停 CPAM 前端的被动读取与渲染，绝不能暂停服务器端调度、自动恢复、优先级降级、计费或任何 Provider 调用。

## 已确认的交互

在凭证列表工具栏增加 `列表实时刷新` 开关：

- 首次默认 **开启**；值使用浏览器 `localStorage` 保存，刷新页面或重新打开此浏览器仍保持选择。
- 开启时，保留现有全部自动刷新节奏：
  - 当前可见页（最多 50 个账号）的紧凑最近请求索引：10 秒；
  - 当前页历史用量与额度窗口：60 秒；
  - 仅在“最近请求”排序时的全局紧凑索引：30 秒；
  - Header 快照 / 巡检摘要的被动读取：60 秒；
  - 降优先级结果的增量 UI 同步。
- 关闭时，列表保持在最后一次取得的快照。上述**所有前端自动读取和 UI 合并**停止；当前筛选、排序、分页、最近 9 请求条、失败原因、历史用量与额度窗口不会自行变化。
- 关闭不影响后台：CPA/CPAM 仍继续调度、计费、健康巡检、自动更新、自动恢复和 502/503/429/500 等错误的优先级策略。暂停的是浏览器展示，不是服务器工作。
- 顶部现有 `刷新` 按钮在关闭状态仍可用，执行一次人工快照刷新；不会反向打开开关。
- 现有 `刷新额度` 按钮语义不变：它是显式的额度刷新操作；新的实时刷新开关及顶部普通 `刷新` 不会主动触发 Provider 额度查询、Token 写入或计费变更。
- 重新开启时立即触发一次当前页面的轻量同步；若当前排序为“最近请求”，同时补一次全局紧凑索引。之后恢复既有 10 / 30 / 60 秒节奏。

## 推荐实现：方案 A（已选择）

### 状态与持久化

新增 `useLocalStorage<boolean>('accountsPage.liveRefreshEnabled', true)`，并以此派生 `accountsLivePollingEnabled`：

```text
activeView === 'accounts' && documentVisible && liveRefreshEnabled
```

开关显示在列表工具栏，文案为 `列表实时刷新`。关闭时显示 `已冻结` 和最后一次成功自动/人工数据同步时间，避免把静态快照误认成实时数据。

### 数据流边界

| 数据流 | 开启 | 关闭 | 恢复 |
|---|---|---|---|
| 可见页 `account-recent-index` | 每 10 秒 | 停止 | 立刻拉取当前页 |
| 当前页 `account-history` / `account-window-usage` | 每 60 秒 | 停止 | 立刻拉取当前页 |
| 全局最近请求紧凑索引 | 仅最近排序时每 30 秒 | 停止 | 最近排序时立刻拉取 |
| Header / 巡检摘要 | 每 60 秒 | 停止 | 立刻拉取一次 |
| `server-error-priority-demotions/updates` UI 投影 | 增量轮询 | 停止 | 从暂停前游标补读 |

页面首次进入、分页、筛选或排序产生的**显式上下文变化**仍加载该新上下文所需的数据；这不是后台定时刷新。关闭后不会把空白页留给用户。

### 降优先级更新游标

`useServerErrorPriorityUpdates` 目前在不活跃时会初始化新的短回溯游标。为保证人工冻结期间的变化不丢失，改为：

1. 关闭实时刷新时中止尚未完成的请求，但保留最后一个已确认 `nextCursor`；
2. 重新开启后从保留游标继续拉取，按服务端顺序合并全部缺失的终态记录；
3. 只有连接范围（地址/管理密钥）真正变化时才重新建立初始游标。

因此恢复画面时会追平已发生的降优先级，不会把暂停期内的变化遗漏为“未发生”。

## 非目标与安全边界

- 不更改任何后端 API、CPA Core、认证文件、代理、SQLite、计费或额度计算。
- 不取消已有手动按钮，不修改“刷新额度”的 Provider 调用语义。
- 不改变最近请求筛选器的阈值、排序规则或分页语义。
- 不创建全量账号重算；恢复时也只按现有的可见页/紧凑索引路径请求。

## 验收与测试

1. 默认开启，且刷新浏览器后偏好保留；新浏览器默认开启。
2. 关闭后推进假定计时器，10/30/60 秒请求均不发出；页面证据不改变。
3. 关闭状态点击顶部普通 `刷新`，仅产生一次人工读取且仍保持关闭。
4. 开启后立即刷新当前页；最近排序额外刷新全局索引；非最近排序不得请求全局索引。
5. 暂停期间产生的降优先级更新，在重新开启后从游标补齐一次且不重复应用。
6. Accounts 页面现有测试、TypeScript、构建通过；审阅变更确认没有额度/Token/计费写入路径。
